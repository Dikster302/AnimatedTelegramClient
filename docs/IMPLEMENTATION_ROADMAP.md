# Specialgram — план реализации

Основной стек: Java + Kotlin, Android Views, TDLib, Firebase, C/C++ JNI.
Идентификатор приложения сохраняется: `com.dikster.specialgram`.
Jetpack Compose не используется.

## Этап 1 — нативная основа
- [x] Удалить Compose plugin, Compose build feature и Compose dependencies.
- [x] Централизовать цвета и размеры дизайн-системы.
- [x] Добавить общие анимационные помощники на Android View.
- [ ] Перевести основные экраны на единые токены темы.
- [ ] Выделить единый фасад TDLib и закрепить владение его жизненным циклом.

## Этап 2 — данные и TDLib
- [ ] Разделить UI-контракты и TDLib-команды через репозитории.
- [ ] Добавить Room-кэш чатов/сообщений с миграциями и политикой очистки.
- [ ] Сохранить единый поток обновлений TDLib и обработку ошибок.
- [ ] Проверить пагинацию истории, непрочитанные счётчики и повторные запросы историй.

## Этап 3 — интерфейс
- [ ] Список чатов, фильтры, закрепление, архив и поиск.
- [ ] Экран переписки, группировка пузырей, статусы отправки и реакции.
- [ ] Истории: сегментный прогресс, свайпы, публикация и просмотр.
- [ ] Профиль и настройки в общей дизайн-системе.

## Этап 4 — медиа и системные функции
- [ ] Фото, видео, файлы, стикеры и голосовые сообщения.
- [ ] Lottie-анимации только для сложных сценариев; базовые переходы остаются нативными.
- [ ] FCM, Crashlytics и восстановление после сетевых ошибок.
- [ ] Аудиозвонки — только после проверки полного TDLib/tgcalls native lifecycle.

## Проверки
- Каждая функция разрабатывается в отдельной ветке `feature/*`.
- CI-компиляция не считается проверкой на реальном устройстве.
- APK создаётся отдельно, только для этапа тестирования/релиза.
- Не менять `applicationId` и ключ подписи без отдельного плана миграции.
